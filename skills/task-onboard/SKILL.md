# task-onboard

사용 시점: 과제 시작 0분, 계획 세션(docs/plan)에서 바로. 도는 동안 사용자는 README를 읽고, 이 스킬의 질문 후보를 참고해 1차 질문을 자기 말로 보낸다.

## 절차

1. `~/README.md`를 읽고 제출물 파일명·필수조건을 목록으로 옮긴다.
2. 작업 폴더의 구성을 본다: `~/data/` 유무와 파일 형식(csv·xlsx·json·로그·문서), `~/src/` 등 기존 코드 유무, 테스트 유무. 파일은 첫 20줄만 읽는다.
3. 아래 표로 유형을 고른다. 둘 이상에 걸치면 주 유형 하나와 보조 유형 하나를 적는다.

| 유형 | 신호 | 플레이북 |
|---|---|---|
| A 데이터→화면/리포트 | data/에 표 데이터, "화면·대시보드·요약·리포트·CSV" 요구 | `/tmp/kit/playbooks/A-data-web.md` |
| B 기존 코드 수정 | src/·test/가 이미 있고 "버그·기능 추가·회귀" 요구 | `/tmp/kit/playbooks/B-code-fix.md` |
| C 문서·지식 응답 | 문서(SOP·가이드·FAQ)가 주어지고 "질문에 답·검색·가이드" 요구 | `/tmp/kit/playbooks/C-doc-qa.md` |
| D 그 외 | 위에 안 맞음 | A 플레이북을 기본으로 쓰고 차이를 RUNPLAN에 적는다 |

4. `/tmp/kit/catalog.md`에서 계층별 후보를 고르고, 각 행에 **근거(왜 이것)·대안과 미선택 이유·설치 필요·위험**을 붙인 스택 후보 표를 만든다. 외부 패키지·타인 저장소는 후보에 넣지 않는다. "사용자 결정" 열은 비워 둔다.
5. 고른 각본을 **출발점**으로 읽고, 이 과제에 맞춰 **맞춤 표**를 만든다: 각본·템플릿·뼈대의 항목마다 "그대로 / 바꿈(무엇을 왜) / 버림(왜)" 중 하나. 과제가 기본 스택(표준 모듈·메모리 저장·인라인 UI)과 맞지 않으면 차이와 이유를 적고 대안을 제시한다. 정하지 않는다.
6. `docs/plan/RUNPLAN.md`를 만든다: 유형과 근거, 제출물 체크리스트, **스택 후보 표**, **맞춤 표**, v0 정의(45분), 기능 루프 후보 3개, 검증 포인트, 이 과제만의 차이점, 담당자에게 추가로 물을 것 2개.
7. 완료 보고: 유형과 근거 2줄, 스택 후보 표와 맞춤 표에서 **사용자가 결정해야 할 항목 3개 이내를 질문 형태로**(예: "저장은 메모리 그대로 둘까요, 과제가 수만 행이라 SQLite로 바꿀까요?"), RUNPLAN 경로, 담당자에게 보낼 1차 질문 후보 4개(업무 언어). 사용자의 답을 받기 전에는 다음 단계로 가지 않는다. PRD는 이 스킬에서 쓰지 않는다(담당자 답변 정리 후 P1에서).

## 규칙

- 3분 안에 끝낸다. 저장소 전체를 읽지 않는다.
- 해법·스택·점수 규칙을 정하지 않는다. 각본은 지도이지 명령이 아니다. **과제가 각본과 다르면 각본이 아니라 과제를 따른다.** 결정은 사용자가 PRD(P2)에서 한다.
- 담당자에게 물을 질문은 업무 언어로. 이미 README에 답이 있는 것은 넣지 않는다.
- `docs/plan/RUNPLAN.md` 외의 파일은 만들지 않는다.
