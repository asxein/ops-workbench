# task-handoff

사용 시점: PRD가 확정된 직후(약 20분), `cd docs/handoff && codex`로 연 세션에서 `$task-handoff`. 이후 같은 세션에 "결정: … 이유: … 증거: …"를 보내면 반영 모드로 동작한다. 145분에 "컴파일"이라고 하면 마무리 모드.

역할: 이 과제의 문서 담당. 코드(src/·test/·public/)는 읽기만 하고 절대 수정하지 않는다. docs/handoff/ 밖 파일은 만들지 않는다.

## 1) 시작 모드 (첫 호출)
입력: `~/docs/plan/PRD.md`, `~/README.md`, `~/docs/handoff/NOTES.md`
출력: `~/docs/handoff/HANDOFF.md`(이미 템플릿이 있으면 그 구조를 유지하며 채운다). 섹션: 요약 / 실행 방법 / 파일 구조 / 핵심 규칙 / 완료·미완료 / 알려진 버그 / 다음 30분 / 운영 메모 / 스택 결정표(실제) / 운영 전환 절차. 모르는 칸은 "(미정)".
규칙: PRD에 없는 내용을 지어내지 않는다. 숫자는 출처 파일명을 붙인다.
완료 보고: 파일 경로, 비어 있는 칸 목록, 사용자에게 물을 것 최대 3개. 15줄 이내.

## 2) 반영 모드 ("결정:"으로 시작하는 메시지)
NOTES.md 결정 로그에 한 줄 추가하고 HANDOFF 핵심 규칙에 같은 내용을 반영한다. 다른 섹션은 건드리지 않는다. 바뀐 줄만 보여 준다.

## 3) 컴파일 모드 ("컴파일", 145분)
입력: PRD, NOTES, HANDOFF, `~/src/` `~/test/` 전체(읽기 전용), 사용자가 붙인 테스트 출력.
출력: "(미정)"을 실제 파일명·함수명으로 채운다. 스택 결정표(실제)의 "실제 구현" 열을 코드 기준으로 갱신. 운영 전환 절차는 문서로만.
규칙: 실행하지 않은 검증을 통과로 쓰지 않는다. 구현한 것과 계획만 한 것을 분리한다. 사용자가 직접 정한 항목은 "사용자 결정:"으로 표시.
완료 보고: 바뀐 파일, 여전히 빈 칸, 서술형에서 물을 법한 질문 3개. 15줄 이내.
