# 플레이북 C — 문서·지식 응답 (검색·가이드·Q&A)

신호: SOP·가이드·FAQ·매뉴얼 같은 문서가 주어지고, 질문에 답하거나 적절한 절차를 찾아 주는 도구를 요구한다.

> 이 각본은 **출발점이지 명령이 아니다.** 온보딩에서 항목마다 "그대로 / 바꿈 / 버림"을 사용자와 정한 뒤 쓴다. 과제가 각본과 다르면 과제를 따르고, 차이를 RUNPLAN에 적는다.

## 파이프라인 (고정, 외부 API 없음)

문서 로더 `src/ingest.mjs`(md·txt·csv → 조각 배열: 제목·본문·출처) → 색인 `src/index.mjs`(토큰 분해, 소문자화, 간단한 역색인 또는 BM25 유사 점수) → 검색 `src/search.mjs`(상위 N 조각 + 출처) → `src/server.mjs` /api/search → `public/index.html`(질문 입력, 결과 목록, 출처 표시)

외부 LLM API는 쓸 수 없다고 가정한다. "답 생성"이 요구되면 **상위 조각을 출처와 함께 그대로 보여 주는 것**이 v0이고, 요약은 규칙 기반(첫 문장·핵심 줄)으로만.

## v0 정의 (45분)

문서 로드 → 조각화 → 키워드 검색 → 상위 5개 조각과 출처를 화면에. 테스트: 조각화 2개, 검색 순위 2개.

## 기능 루프 후보

1. 동의어·약어 사전(담당자가 쓰는 말 ↔ 문서 용어)
2. 조각 단위 조정(절차 단계를 끊지 않게)
3. "답을 못 찾았을 때" 처리(관련 문서 제안, 담당 부서 안내)
4. 자주 묻는 질문 캐시 — 시간이 남을 때만

## 검증 포인트

- 담당자가 준 실제 질문 5개로 상위 결과에 정답 조각이 있는가(없으면 사전·조각화부터)
- 빈 질문, 오타, 영문·한글 혼용
- 출처 없는 답은 없는가(모든 결과에 파일명·절 번호)
- 문서에 없는 질문에 "없다"고 답하는가(지어내지 않기)

## 흔한 함정

- 벡터·임베딩·외부 API 시도 → 설치·네트워크 불가 가능성, 금지
- 문서 전체를 한 조각으로 → 검색 품질 바닥
- 답 생성에 집착 → 출처 제시가 평가 기준
