# 플레이북 A — 데이터 → 화면/리포트

신호: 표 데이터(csv·xlsx·json)가 주어지고 조회·필터·우선순위·집계·요약·CSV 내려받기 같은 요구가 있다.

> 이 각본은 **출발점이지 명령이 아니다.** 온보딩에서 항목마다 "그대로 / 바꿈 / 버림"을 사용자와 정한 뒤 쓴다. 과제가 각본과 다르면 과제를 따르고, 차이를 RUNPLAN에 적는다.

## 파이프라인 (고정)

입력 어댑터 `src/ingest.mjs` → 정제 `src/clean.mjs`(순수 함수) → 핵심 규칙 `src/rules.mjs`(순수 함수) → 집계 `src/summary.mjs` → `src/server.mjs` /api/* → `public/index.html` 한 장 → 출력 파일(CSV BOM, Markdown 리포트)

scaffold/에서 그대로 쓰는 것: server, csv, repo, index.html 틀, 테스트 틀. 현장에서 만드는 것: ingest 어댑터(형식별), clean 규칙, rules, summary.

## v0 정의 (20~65분의 45분)

입력 파일 → 정제(중복·공백·대소문자·결측 표시) → 핵심 규칙 1개 → 표 한 장에 표시. 테스트: clean 3개, rules 3개. 이게 돌면 커밋·태그 v0.

## 기능 루프 후보 (65~120분, 담당자 답변 순으로)

1. 필터·정렬(담당자가 "먼저 봐야 한다"고 한 축)
2. 묶기·랭킹·근거 표시(규칙의 "왜"를 화면에)
3. 요약 출력 파일(CSV BOM 또는 Markdown) + 내려받기
4. 이상 징후·추세(최근 N일 대비) — 시간이 남을 때만

## 검증 포인트 (V1·V3)

- 경계값: 빈 파일, 헤더만, 중복, 결측, 범위 밖 값, 대소문자·공백, 날짜 형식 혼재, 식별자 오타
- 표본 수가 적은 집계를 과대 해석하지 않는가(표본 수 표시)
- 민감 식별자 마스킹 여부, 원본 파일 미수정, 0.0.0.0 + PORT
- 담당자가 말한 실제 사례가 상위 결과에 들어오는가(사례가 데이터에 실제로 있는지 grep으로 먼저 확인)

## 흔한 함정

- 담당자가 말한 사례·필드가 데이터에 없는데 규칙을 만든다 → 데이터에서 확인 후 없으면 "가정:"
- 업로드 UI, 로그인, 차트 라이브러리 → 제외. 고정 경로 읽기 + 인라인 표
- 제출물 외 산출물(벤치마크·스크린샷·검증 폴더) → 만들지 않는다

## RUNPLAN 틀

```
# RUNPLAN
- 맞춤 표: | 항목 | 그대로/바꿈/버림 | 이유 | (뼈대 파일, 문서 템플릿 섹션, 세션 구성, 스택 결정표 행마다)
- 유형: A (근거: …)
- 제출물 체크리스트: …
- v0: 입력 … → 규칙 … → 화면 …  (45분)
- 기능 루프 후보: 1 … 2 … 3 …
- 검증 포인트: …
- 이 과제만의 차이: …
- 담당자 추가 질문: 1 … 2 …
```
