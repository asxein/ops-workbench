# 수동 UI·데이터 검증 카드 (내가 직접, 5분)

에이전트는 curl·단위 테스트까지만 한다. 브라우저 화면, 실제 데이터 투입, 내려받은 파일 열기는 내가 한다. 결과는 아래 표로 `docs/plan/REVIEW.md`에 붙인다. 스크린샷은 못 남기니 **시각·입력·기대·실제** 네 칸이 증거다.

## 언제

- 65분 v0 직후 (A1~A5)
- 기능 하나 끝날 때마다 (해당 줄만)
- 120분 사전 부검 때 전체 한 번
- 158분 인수자 읽기 때 HANDOFF의 실행 명령으로 다시 한 번

## 표 (복사해서 채운다)

| # | 시각 | 어디서 | 입력·조작 | 기대 | 실제 | 판정 | 조치 |
|---|---|---|---|---|---|---|---|
| A1 | | Browser 탭 `/` | 첫 화면 로드 | 표에 데이터 행 N개, 기준 시각 표시 | | | |
| A2 | | 필터 | 가장 자주 쓸 필터 1개 선택 | 건수가 줄고 다른 행이 안 섞임 | | | |
| A3 | | 정렬·우선순위 | 기본 정렬 상태 | 담당자가 말한 "먼저 봐야 할 것"이 맨 위 | | | |
| A4 | | 내려받기 | CSV/리포트 내려받기 | 파일이 열리고 한글 안 깨짐(BOM), 열 구성이 PRD와 같음 | | | |
| A5 | | 경계값 | 빈 필터·없는 값·대소문자 섞어 입력 | 빈 결과 메시지 또는 정상 매칭, 오류 화면 없음 | | | |
| B1 | | 데이터 | 담당자가 말한 **실제 사례** 1건을 찾는다(grep으로 먼저 존재 확인) | 화면 상위에 보인다 | | | |
| B2 | | 데이터 | 원본에 있는 품질 문제 1건(중복·오타·결측)이 화면에 어떻게 나오나 | 정제 규칙대로(합쳐짐·보정·"알 수 없음") | | | |
| C1 | | 재시작 | 서버 끄고 `PORT=다른값`으로 재실행 → Browser 포트 바꿔 연결 | 그대로 동작 | | | |
| C2 | | 민감 정보 | 화면·API 응답·내려받기 파일에서 마스킹 대상 검색 | 원문 없음 | | | |

판정은 통과 / 실패 / 미확인 셋 중 하나. **미확인은 통과가 아니다.** 실패는 M3로, 못 고치면 HANDOFF 한계로.

## 요령

- 입력은 **데이터에 실제로 있는 값**으로 한다. 담당자 사례는 먼저 `grep`으로 존재를 확인한다.
- 한 줄 확인에 30초를 넘기지 않는다. 막히면 "미확인"으로 적고 넘어간다.
- 내려받은 CSV는 에디터로 열어 첫 줄(BOM·헤더)과 한글 열 하나만 본다.
- 이 표의 실패 항목이 곧 서술형 "검증한 것과 안 한 것" 질문의 답이다.
